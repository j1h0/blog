[공유] 8.15 중.일 사이버전 관련

중국... 이 .. 나쁜놈들....15일날 쉬지도 못하게 하네 ㅠ.ㅠ

최근 중국 중국홍객연맹(中國紅客聯盟•중홍련)에 의해 8월 15일 일본 내 반 중국 사이트 공격에 한국 주요사이트가 경유지로 활용 될 수 있다는 언론보도가 확인됨에 따라 이에 대응 하기 위해 모니터링을 강화하고 침해사고 예방 및 피해가 최소화 될 수 있도록 대비하고자 함
1. 언론 보도 자료
1.1 동아일보 2005.07.14
“中해커 4만명, 한국서버 경유 日공격…내달 15일”
8월 15일을 기해 중국의 해커들이 한국 내 서버를 ‘공격 중간루트’로 삼아 일본의 각종 인터넷 사이트를 대규모 해킹할 것으로 알려져 논란이 일고 있다. 특히 중국 해커들이 인터넷 주소(IP) 추적을 피하기 위해 경유하려는 한국 내 서버는 대학뿐 아니라 일부 정부기관까지 포함된 것으로 알려져 파문이 예상된다. 홍콩의 원후이(文匯)보는 2일 “세계 5대 해킹 조직인 ‘중국홍객연맹(中國紅客聯盟•중홍련)’이 7∼9월 일본 내 반중국(反中國) 웹 사이트들에 대해 대규모 해킹을 계획하고 있다”고 보도했다. 중홍련은 베이징(北京)대 산하 사회과학원 학생 및 졸업자를 주축으로 구성된 중국 내 최대 해킹조직이다.
원후이보는 또 중홍련이 3개 조로 편성돼 △정보 수집조는 일본 사이트들의 허점을 파악하고 △보수 유지조는 일본 측의 반격에 대비하며 △공격조는 왜곡교과서로 문제가 된 후소샤(扶桑社) 사이트 등 일본 내 반중국 웹 사이트들을 공격할 계획이라고 덧붙였다. 이와 관련해 중홍련 소속의 한 해커는 최근 한국 측 지인에게 “이 공격에는 한국 내 3개 대학과 온라인 게임업체의 서버가 경유지로 검토된 상태”라며“이들 서버는 의외로 보안에 취약해 IP 세탁에 적절한 것으로 나타났다”고 밝혔다. 그는 “13일 현재 해킹에 동참키로 한 중국 해커는 4만5000명에 달한다”면서 “8월 15일을 지켜보라”고 말했다.
중국 해커들이 한국 서버를 경유지로 삼으려는 이유는 올 4월 중국 전역에서 일어난 대규모 반일시위와 때맞춰 중국 해커들이 일본의 웹 사이트를 공격했으나 일본 측이 중국 측 IP를 모두 차단하면서 공격이 무산됐기 때문. 중국 해커들이 한국을 경유해 일본의 웹 사이트를 공격한다면 일본 측도 IP 차단이 힘들다는 계산을 한 것으로 보인다. 이에 대해 원광대 한성국(컴퓨터공학과) 교수는 “만일 중국 해커들이 한국의 서버를 자유자재로 이용하게 방치한다면 사이버 정보전쟁에서 한국의 국토를 내주는 꼴이 된다”며 “국내 서버를 허가 받지 않고 경유한다는 것은 그 안의 정보까지 쉽게 조작할 수 있다는 뜻이 된다”고 지적했다

2. 예상 피해 분석 현황
2.1 주요 사이트 해킹 공격 시
- 일본측 대응 시(IP 차단 및 역공격) 중간 경유지로 사용된 한국내 서버들에 대한 IP 차단 및 역공격을 받을 가능성이 있어 한국과 일본과의 분쟁 가능성 내포
- 침해 사고에 따른 서비스 지연 및 장애 발생 가능
- 중∙일 사이버전쟁과 관련한 국내 홈페이지 변조사고 급증 예상
2.2 서비스 거부 공격 시
- 트래픽 폭주로 인하여 Bandwidth 고갈 및 네트워크 장비에 부하가 발생하여 장애 발생 및 해당 네트워크 장비를 이용하는 서버들의 서비스 지연 및 서비스 거부 가능
- 공격 대상인 일본 주요 사이트에 대한 DNS 쿼리가 폭주하여 DNS 서비스 지연 및 서비스 거부 가능
2.3 예상 공격 기법
- 최근 발생되었던 중국 해커들에 의한 공격 패턴을 보면 기존에 발견된 공격 기법들을 자동화된 툴을 이용한 무작위 공격이 주로 활용
- 자동화된 공격 툴을 이용한 무작위 공격이 주를 이룰 것으로 판단
2.3.1 Sql Injection
 윈도우 시스템의 MS-SQL사용 시 Store Procedure 기능을 이용한 administrator 권한 획득이 가능함.
 Sql Injection 자동화 툴은 이미 인터넷에 배포된 상태: HDSI, MSSQL WEB SHELL, NBSI 등
2.3.2 WEB Back Door
 Web 취약점을 이용하여 html 파일에 악성 스크립트를 숨겨 놓아 사용자가 해당 페이지를 Access 하였을때 악성 스크립트가 자동으로 실행되고 스크립트를 실행한 사용자의 권한을 획득할 수 있다.
2.3.3 Terminal Service
 터미널 서비스가 open 되어 있는 경우 무차별 공격을 통해 로그인 할 수 있음: Recton
2.3.4 SSH Brute force
 최근 들어서 SSH 사용포트인 TCP/22대하여 Brute Force 공격시도가 자주 발생
 대부분 중국IP가 공격자IP로 확인되고 있어 주의가 필요함
2.3.5 MS SQL 공격
 MS-SQL은 설치 시 SA 계정이 기본적으로 생성된다. 이때 주로 패스워드가 설정되지 않아 이러한 취약점을 가진 MS-SQL을 스캔한 후, admin, root, sa 등의 쉬운 암호를 이용하여 로그인을 시도한다. 이에 감염된 시스템의 시스템 정보 및 사용자 정보는 백도어 제작자에게 유출될 수 있다. 이 취약점은 Spida 웜, 각종 Bot(BackDoor.IRC.Moto)류에 악용될 가능성이 높다.

3. 집중 모니터링 방안
3.1 특정 포트 Traffic 모니터링
- 22/TCP(SSH), 25/TCP(SMTP), 1434/TCP(MS-SQL), 3389/TCP(Terminal Service)
3.2 예상 공격 기법 모니터링
3.2.1 Sql Injection
 입력 문자열에 ‘ , or , = , \ , > 와 같은 특수 문자 필터링
 Web log 모니터링을 하여 같이 EXEC 문자열이나, XP_CMDSHELL, Net, user, Update, Insert 명령이 사용되는지 확인
3.2.2 Microsoft IIS WebDAV 공격
 Microsoft Windows의 ntdll.dll Overflow 취약성을 공격하는 IIS WebDAV 요청을 탐지한다. WebDAV 명령의 파라메타 값이 길어서 버퍼오버플로우가 일어날 수 있거나, 공개된 exploit을 이용한 공격시도인지 raw data를 확인한다.
 Web log 모니터링을 하여 WebDav 파마메타 값이 비정상적인 값이 채워지는 확인
3.2.3 Microsoft Windows DCOM RPC Interface Buffer Overrun 공격
 Windows "client DCOM object activation 요청"을 이용한 Microsoft Windows DCOM RPC Interface Buffer Overrun 취약성 공격 실행을 탐지한다.
3.2.4 Microsoft Internet Explorer IFRAME 공격
 IFrame의 SRC 파일 이름을 이용한 공격파일의 다운로드를 탐지한다. 탐지된 이벤트의 목적지 시스템으로 파일이 전송되었으므로 파일이 내려간 후 그 시스템에서의 명령 실행성공 여부를 확인해야 한다.
3.2.5 'zeroboard의 cross site 스크립트' 공격
 외부 사이트의 악성파일 실행에 이용되는 cross site 스크립트 취약성이 있는 zeroboard의 페이지(Write.php,_head.php등)를 이용한 공격 시도를 탐지한다. raw data를 확인해서 악성 외부 파일 실행시도를 확인한다.
3.2.6 MS-SQL 서버 공격
 SA 계정 암호 설정: 최적의 공격방지대책으로 SA 계정의 패스워드를 설정해야 하며, 패스워드 자체 또한 쉽게 추측 되지 않게 하는 것이 좋다. 이는 SQL 서버 설치 시 SA 계정에 대한 암호입력이 필수가 아닌 선택으로 사용자에 의해 간과되기 때문이다. 또는 디폴트 아이디/패스워드인 Sa/Null 계정을 제거하는 방법도 있다.
 xp_cmdshell을 사용권한 제거: Sa/Null 계정을 통해 접근 자체는 문제가 되지 않지만, 접근한 이후에 xp_cmdshell을 이용하여 시스템 관리자의 권한으로 내부 실행 명령어가 가능하다. 그러므로 xp_cmdshell을 사용하지 않을 경우에는 실행 권한을 반드시 제거해야 한다.
 TCP/1433 포트 필터링: TCP/1433 포트로 들어오는 패킷을 차단함으로서 외부망으로부터의 스캐닝이나 본 취약점을 이용한 공격을 방지할 수 있다.
 Egress Filtering: 피해 시스템으로부터 TCP/1433 포트를 통하여 외부망이나 인터넷으로 나가는 패킷을 차단함으로써 또 다른 시스템에 대한 피해를 줄일 수 있다.
3.2.7 웹서버를 통한 시스템 쉘명령 시도
 웹 서버를 통해 UNIX/LINUX 계열 OS의 쉘인 sh, ksh, bash, csh, tcsh, zsh 또는 Windows 명령쉘인 cmd.exe, 또는 root.exe를 실행하려는 시도를 탐지한다. 탐지된 이벤트의 raw data와 근원지 시스템을 파악한다.
3.3 침입 탐지 시 공격 성공/실패 여부 확인
- 공격 시도가 탐지 후 대상자 → 공격자 응답 내용이 있는지 확인하여 공격 성공 시 나타나는 패턴과 비교하여 공격의 성공 여부를 확인한다.
- 대상자 시스템에 대한 분석을 통하여 공격 성공 시 나타나는 영향 및 현상을 비교하여 공격 성공 여부를 확인한다.

4. 침해 대응 방안
4.1 침해 및 공격에 대한 대응 방안
4.1.1 공격자 IP 차단
 사이버안전센터, 한국정보보호진흥원, 국가사이버안전센터의 해킹 요주의 IP목록 Block
4.1.2 특정 서비스 포트 차단 및 변경
 SSH(22/tcp)
 MS-SQL(1434/tcp)
 Terminal Service(3389)
4.1.3 특정 포트에 대한 트래픽 증가 시 해당 IP 차단
 침입차단시스템: 요주의 IP 차단
 침입방지시스템: 요주의 IP 차단
 Router: 요주의 IP ACL deny 적용
4.1.4 Web 취약점 패치
 php, asp, swf 등 web에서 access 가능한 파일 등의 upload 금지 및 patch
4.1.5 패스워드 설정
 무차별 공격에 취약한 암호를 사용하지 않고 특수 문자를 이용한 강력한 패스워드 설정
